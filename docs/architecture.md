# 架构与设计决策

## 设计原则

1. **一层只做一件事**。算法细节不跨层：映射层不做物理约束，成形层不看音频，PWM 层不看特征。
2. **不硬编码魔法数字**。所有可调量集中在 `config.py` 的分组配置对象里，算法模块只读配置。
   这样同一首歌换参数做 A/B 对比时，不需要改代码。
3. **中间产物可落盘、可叠加**。每层的输出都能单独画出来，否则参数只能盲调。

## 三条硬契约

这三条一旦破坏，各映射策略就无法叠加对比，整个调参流程失效。

### 契约一：所有特征共享同一时间栅格

`AnalysisConfig.n_fft / hop_length` 定义了整条链路唯一的时间栅格，
`rms_db`、`spectral_flux`、`spectral_centroid`、`band_ratio`、`f0` 全部等长、等时间轴。

栅格约定：`scipy.signal.stft` 在 `boundary=None` 时不补零居中，
第 i 帧覆盖 `[i*hop, i*hop + n_fft)`，帧时间 `i * hop_s`。RMS 用累积和法独立计算，
严格遵守同一约定，所以它和 STFT 派生的特征天然对齐。

默认 `sr=22050`、`hop=512` → `hop_s ≈ 23.22ms`，即分析栅格 **43.1 Hz**。

### 契约二：映射层输出强制归一化到 [-1,1]

```
Mapper(feat: FeatureTrack, cfg: MappingConfig, rate_per_s: float) -> np.ndarray  # shape (n,), 值 ∈ [-1,1]
```

- `-1` / `+1` = 左右行程极限，`0` = 中位。连续三种模式**以中位数为 0 点**做双侧归一，
  保证静止位居中、两侧对称（`rate_per_s` 只有 beat 用得到，它要按限速反推摆幅）。
- **归一化在映射层内部完成**，这是关键：切换 `--mode` 时，shaping 和 pwm 两层完全不感知，
  各模式的输出是同一种东西，才能直接叠加在同一坐标上对比。
- 统一收尾由 `map_track()` 负责：NaN 清理 → 去毛刺平滑 → 方向翻转 → 增益 → 裁剪。
  各策略函数直接输出 [-1,1]，不重复实现收尾逻辑。

### 契约三：成形层的处理顺序固定

```
分位数归一化 → NaN 填充 → 低通 → 降采样 → 限速 → 死区 → 首尾回中 → 限速（最终钳位）
```

理由见下方「关键设计决策」第 1、2、4 条。

## 分层职责

| 层 | 做 | 不做 |
|---|---|---|
| `source` | 下载、解码、混单声道、重采样 | 不做任何分析 |
| `features` | 帧化 + 五项特征提取 | 不做打分、不做归一化 |
| `segment` | 打分曲线、滑窗选段、onset 吸附、淡入淡出 | 不看音色与音高，只用能量 + 新颖度 |
| `mappers` | 特征 → [-1,1] 行程 | 不做低通、不做限速（那是物理约束） |
| `shaping` | 低通、降采样、限速、死区、回中 | 不看音频，只处理信号本身 |
| `pwm` | 标定、50Hz 插值、脉宽钳制 | 不做平滑、不做限速 |
| `pipeline` | 串联、传数据、多模式并列 | 不含任何算法细节 |
| `viz` | 三行对比图 | 不改数据 |

## 为什么是「双级特征提取」

整首音频过一遍 `features`，截出的片段再过一遍，这是刻意设计而非冗余：

- **整首那次** 服务高潮截取。判断「哪一段最像副歌」必须看全局，局部看不出相对强弱。
- **片段那次** 服务映射。原因有两个：
  1. 若沿用整首的特征，映射层的分位归一化会被整首的动态范围污染——
     副歌的分位数会被主歌的安静段落拉低，行程压不满。
  2. 片段特征的时间轴必须**归零**（第一帧 = 0s），才能和 PWM 帧序列、CSV 一一对齐。

代价是特征提取跑两遍（含两遍 YIN）。离线处理，可接受。

## 关键设计决策

### 1. 降采样必须排在低通之后

先抽点再滤波，高于新采样率一半的频率会折叠成低频假信号（混叠）。
混进来的假摆动在时域上看起来像真实的慢速运动，**再怎么限速也去不掉**，只能重新滤波。
所以顺序不可交换：先把 43.1Hz 栅格限制在 4Hz 以内，再降到 25Hz。

### 2. 限速必须排在降采样之后

限速的单位是「单个控制帧允许的最大位移」。控制帧率降到 25Hz 后帧间隔变长，
单步允许的位移才相应变小。如果在原始 43.1Hz 栅格上按同样的 `max_rate_per_s` 限速，
单步上限会大到几乎不起作用。

默认 `max_rate_per_s = 2.0`，`control_hz = 25` → 单步上限 **0.08**，
即 0.5s 走完全程（归一化行程 ±1）。

### 3. 舵机带宽是硬约束，映射层禁止做高频尖锐映射

普通模拟/数字舵机的有效带宽只有 **3~5Hz**。
高于此频率的指令舵机根本跟不上，只会变成抖动、发热和齿轮磨损。
因此低通取 4Hz 折中，且映射层只做「去毛刺」级别的轻微平滑（默认 50ms），
真正的带宽约束留给成形层，避免两处各自为政。

### 4. 回中之后追加一次限速 —— 对原定顺序的一处偏离

原定顺序把「首尾回中」放在最后。但回中的做法是用斜坡乘信号，当片段**开头本身还在快速上升**时，
斜坡与信号的乘积仍可能产生超过单步上限的位移；同理，回中斜坡若按限速反推长度，
在信号同时变化的情况下也不足以严格保证约束。

物理约束是硬约束，不能为了顺序好看而破例。所以：

- 回中斜坡长度取 `max(center_ms, 按限速反推的最短时间)`；
- **回中之后再压一次限速**，这一遍只做安全钳位，正常情况下几乎不改变波形。

好处是「起点严格为 0」与「终点回到中位附近」同时成立，且全程单步位移可证明不超过上限。

### 5. 脉宽保守钳制到 600~2400µs

常见舵机标称行程是 500~2500µs，但两端各留 ~100µs 余量：
机械限位处长时间顶死会导致堵转、电流飙升和舵机烧毁。
宁可牺牲一点角度范围，也不要让舵机在极限位置持续受力。

标定按中心脉宽**分段线性**，允许 `pulse_center_us` 不落在 min/max 正中——
真实舵机的中位往往不是 1500µs。

### 6. 分位归一化而非 min/max，且 0 点取中位数

- 映射层：单个爆音或一个极短的高音会把 min/max 拉开，导致整段行程被压扁，
  永远到不了 ±1。用 2/98 分位可以忽略这些离群值；**0 点固定取中位数**，
  否则中位数落点由特征偏态决定，尾巴会长期停在那一侧。
- 截取层：打分曲线用 5/95 分位，同理防止单个鼓点主导整条曲线。

两处的分位归一化是**两件事**，不要混淆：
映射层决定「特征 → 行程」的形状；成形层只是把已归一的信号再拉满，为限速做准备。
`beat` 模式例外——它会跳过成形层这一步（`rescale=False`），因为它的摆幅是按限速
刻意算小的，拉满会让斜率超限、极值漂离拍点。

### 7. 多模式共用同一套下游配置

`pipeline._build_mapping()` 对每个模式只替换 `MappingConfig.mode`，
`shaping` / `servo` 配置各模式完全共享。
这样「各条曲线的差异」100% 来自映射策略本身，不会混入下游参数差异。
另有 `mappers.ORDER` 固定展示顺序，保证同一首歌每次跑出来的颜色与图例位置一致，便于跨次对照。

## 编排对象

```python
PipelineConfig(source, analysis, segment, mapping, shaping, servo)   # 六组配置

PipelineResult(
    source, cfg, pcm, sr,
    track,        # 整首特征
    score,        # 整首打分曲线（供出图复用，避免重算）
    clip,         # 高潮段
    clip_track,   # 片段特征，时间轴归零
    mappings,     # list[MappingResult]，一个模式一项
)

MappingResult(mode, raw, shaped, pwm)   # 单模式的完整链路产物
```

`MappingResult` 是 A/B 对比的最小单位：三层中间产物都在里面，出图时直接叠加。

## 配置对象分组

| 配置 | 管什么 | 关键参数 |
|---|---|---|
| `SourceConfig` | 输入与解码 | `sr`、`max_duration_s`（只加载前 N 秒，调试用） |
| `AnalysisConfig` | 帧化与特征 | `n_fft`、`hop_length`、频段边界、f0 搜索范围与浊音阈值 |
| `SegmentConfig` | 高潮截取 | `window_s`、`smooth_s`、能量/新颖度权重、onset 吸附、手动覆盖 |
| `MappingConfig` | 映射策略 | `mode`、`invert`、`gain`、分位点、音高上下限 |
| `ShapingConfig` | 物理约束 | `lpf_hz`、`control_hz`、`max_rate_per_s`、`deadzone`、`center_ms` |
| `ServoConfig` | PWM 标定 | `pwm_hz`、脉宽 min/max/center、`angle_max_deg` |

参数逐项说明与调参建议见 [tuning.md](tuning.md)。
