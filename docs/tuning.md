# 参数速查与调参

本文是调参时的手边参考，分三部分：

1. **参数速查** —— 六组配置对象的逐项说明、默认值、对应 CLI 开关与调参建议。
2. **验收判据** —— `tools/verify_segment.py` 断言的契约清单，改动后必须全部成立。
3. **实测基线与调参发现** —— 在合成测试音频上的实测数值，以及由数据得出的调参经验。

算法原理见 [algorithms.md](algorithms.md)，设计理由见 [architecture.md](architecture.md)。

## 参数速查

所有可调量集中在 `music2servo/config.py` 的六组 dataclass 里，算法模块不硬编码魔法数字。
CLI 为 `--` 的项表示只能改代码（对应开关未暴露到命令行）。

### SourceConfig —— 输入与解码

| 参数 | 默认 | CLI | 说明 / 调参建议 |
|---|---|---|---|
| `sr` | `22050` | `--sr` | 统一重采样目标。舵机只响应 3~5Hz，调高采样率只增加算力不改变结果。 |
| `max_duration_s` | `None` | `--max-seconds` | 只加载前 N 秒。**调试利器**：先切 10s 把截取和映射跑通，再放全长。 |
| `url_timeout_s` | `30.0` | — | URL 下载超时。网络慢时调大。 |

### AnalysisConfig —— 帧化与特征

| 参数 | 默认 | CLI | 说明 / 调参建议 |
|---|---|---|---|
| `n_fft` | `2048` | `--n-fft` | STFT 窗长。22050Hz 下约 93ms，兼顾频率分辨率与时间分辨率。 |
| `hop_length` | `512` | `--hop` | 帧间隔，与 `n_fft` 共同定义**唯一时间栅格**（默认 43.1Hz）。改动会同时影响所有特征与下游帧数。 |
| `band_low_hz` | `(30, 250)` | — | `band_ratio` 低频段边界（左闭右开）。想强调鼓/贝斯时把上界抬高。 |
| `band_high_hz` | `(2000, 8000)` | — | 高频段边界。想强调镲/气声时把下界降低。 |
| `f0_min_hz` | `80.0` | — | f0 搜索下界，低于此视为无基频。男低音可降到 60~70。 |
| `f0_max_hz` | `1000.0` | — | f0 搜索上界。搜索范围越宽 τ 越多，YIN 越慢。 |
| `f0_voiced_ceiling` | `0.35` | — | 浊音判决阈值。实测纯音/和音 ≈0.00~0.01、白噪 ≈0.88、粉噪 ≈1.62，区分度极大，0.35 很宽松，一般不用动。 |

> `n_fft / hop_length` 是全局契约，改它等于换时间栅格，`verify_segment.py` 里的帧数判据要一起复核。

### SegmentConfig —— 高潮截取

| 参数 | 默认 | CLI | 说明 / 调参建议 |
|---|---|---|---|
| `window_s` | `20.0` | `--window` | 目标片段长度上限。比整首长时取整首。 |
| `smooth_s` | `1.5` | `--smooth` | 打分曲线平滑窗口。**太小会吸附到单个鼓点，太大会糊掉段落边界**，是最常动的一个。 |
| `energy_weight` | `0.7` | `--energy-weight` | 能量在打分里的权重。想让「最响段」胜出就调高。 |
| `novelty_weight` | `0.3` | `--novelty-weight` | 新颖度（谱通量）权重。想让「有新声音进入的段落」胜出就调高。 |
| `norm_low_pct` / `norm_high_pct` | `5` / `95` | — | 打分归一化分位。防止单个爆音把整首曲线压扁。 |
| `onset_align_s` | `0.6` | `--onset-align` | 起点向前吸附到 onset 的搜索范围，避免从乐句中间切入。设置为 0 可关闭吸附。 |
| `fade_s` | `0.3` | `--fade` | 片段首尾淡入淡出，防止第一帧角度跳变。片段短于 2×`fade_s` 时自动跳过。 |
| `manual_start_s` / `manual_end_s` | `None` | `--start` / `--end` | 手动指定区间，任一非空即**跳过自动检测**。用于「自动切得不对」时的兜底。 |

### MappingConfig —— 映射策略

| 参数 | 默认 | CLI | 说明 / 调参建议 |
|---|---|---|---|
| `mode` | `"envelope"` | `--mode` | `envelope` / `brightness` / `pitch` / `beat` / `all`（四种叠加对比）。 |
| `invert` | `False` | `--invert` | 翻转方向。舵机装反时用，不影响其它层。 |
| `gain` | `1.0` | `--gain` | 映射后线性增益，再裁剪回 `[-1,1]`。**注意**：极值会被裁剪，放大 `gain` 不总能扩大最终行程，见「调参发现」第 4 条。 |
| `smooth_s` | `0.05` | `--map-smooth` | 仅去逐帧尖峰。真正的带宽约束在 shaping 层，这里**不要**做大平滑。 |
| `norm_low_pct` / `norm_high_pct` | `2` / `98` | `--norm-low` / `--norm-high` | 特征 → 行程的归一化分位，**0 点固定取中位数**（P→-1 / 中位→0 / P→+1）。只定两侧展开的范围；静止位是否居中就靠这一条，否则尾巴会长期停在一侧。比 min/max 稳健，忽略单个爆音。 |
| `pitch_floor_hz` / `pitch_ceil_hz` | `80` / `1000` | `--pitch-floor` / `--pitch-ceil` | `pitch` 模式的对数映射上下限，0 点取两者的**对数中点**（约 283Hz）。**这两个直接决定整段行程怎么展开**，比 `gain` 更该优先调。 |
| `beat_swing_s` | `None` | — | `beat` 模式的摆动周期（秒）= 相邻极值的时间间隔。`None` = 自动检测（取**一拍**，每拍一个极值、左右交替）。摆幅随之按限速反推为 `min(1, max_rate_per_s × 摆动周期 / 2)`：一拍 0.5s 时约 0.50。填成两拍即半速摆动、摆幅翻倍。 |
| `beat_bpm_range` | `(60, 200)` | — | `beat` 自动检测的 BPM 搜索范围。**设窄了会把速度锁到倍数上**，见「调参发现」第 7 条。 |
| `beat_threshold` | `1.5` | — | onset 判决系数：谱通量高于局部中位数 × 该值才算一拍。调低更敏感（细碎鼓点也算），调高只留最重的鼓点。 |
| `beat_min_dynamics_db` | `3.0` | — | 「有没有节拍」的响度动态范围门槛（RMS 的 95 与 5 分位之差）。低于它就判定无节拍、输出静止居中。调成 `0` 关闭这道闸。 |

### ShapingConfig —— 物理约束

顺序固定：分位数归一化 → NaN 填充 → 低通 → 降采样 → 限速 → 死区 → 首尾回中 → 限速（最终钳位）。

| 参数 | 默认 | CLI | 说明 / 调参建议 |
|---|---|---|---|
| `low_pct` / `high_pct` | `2` / `98` | `--shape-low` / `--shape-high` | 成形层分位归一化。与映射层的分位是**两件事**（见「调参发现」第 3 条）。`beat` 模式跳过这一步：它的摆幅是按限速刻意算小的，拉满会让极值漂离拍点。 |
| `lpf_hz` | `4.0` | `--lpf` | 低通截止。舵机带宽 3~5Hz，4Hz 是折中。调高保留更多细节但更抖，调低更顺但吃掉行程。 |
| `lpf_order` | `2` | `--lpf-order` | Butterworth 阶数。配合 `filtfilt` 是零相位，无群延迟。 |
| `control_hz` | `25.0` | `--control-hz` | 控制帧率。**必须低于低通截止的奈奎斯特**，并在低通之后才降采样。 |
| `max_rate_per_s` | `2.0` | `--max-rate` | 限速：归一化行程/秒。2.0 → 单步上限 0.08（@25Hz），0.5s 走完全程。**beat 的摆幅也由它决定**（摆幅 = `min(1, max_rate × 摆动周期 / 2)`），想让节拍摆更大就先调它。 |
| `deadzone` | `0.02` | `--deadzone` | 软死区宽度，抑制零位附近抖动。用「减去宽度」实现，保证连续。 |
| `center_ms` | `300` | `--center-ms` | 首尾回中过渡时长。实际斜坡长度取 `max(center_ms, 按限速反推的最短时间)`。 |

> 限速单步上限恒定满足：`step = max_rate_per_s / control_hz`。改 `control_hz` 时必须同步检查这个值。

### ServoConfig —— PWM 标定

| 参数 | 默认 | CLI | 说明 / 调参建议 |
|---|---|---|---|
| `pwm_hz` | `50.0` | `--pwm-hz` | 舵机刷新率，标准舵机固定 50Hz，一般不动。 |
| `pulse_min_us` / `pulse_max_us` | `600` / `2400` | `--pulse-min` / `--pulse-max` | **保守**取 600~2400（而非 500~2500）。换舵机时按实机标称行程减掉两端各约 100µs 余量。 |
| `pulse_center_us` | `1500` | `--pulse-center` | 中位脉宽。真实舵机中位常不是 1500，按实机测。标定按中心脉宽分段线性，`value=0` 严格对应此值。 |
| `angle_max_deg` | `120.0` | `--angle-max` | 归一化 ±1 对应的机械角度，即舵机单侧最大转角（±120° 为舵机极限）。影响 CSV 的 `angle_deg` 与网页尾巴的刻度/摆幅，**不参与脉宽控制**。 |

## 验收判据

`tools/verify_segment.py` 合成一段结构已知的 80s 音频（副歌 25–55s），端到端断言以下契约。
**改任何一层后都应重跑**，退出码 0 才算通过：

```bash
.venv/bin/python tools/verify_segment.py
```

> 该脚本只跑 `envelope / brightness / pitch` 三种模式；`beat` 的判据另见下文
> 「节拍摆 beat」（`tools/verify_beat.py`）。`--mode all` 现在跑四种，报告图例会比基线表多一行。

### 截取层

| 判据 | 断言 |
|---|---|
| 自动检测 | `clip.auto` 为真 |
| 片段时长 | `|clip.duration_s - window_s| ≤ 0.05` |
| 落点 | `clip.start_s` 落在 `[副歌起点-2s, 副歌终点-window_s+2s]` 内 |
| 能量 | `片段 RMS ≥ 0.85 × 真实高能区 RMS`（基准取真实高能段，不取整首均值） |
| 出图 | 报告 PNG 体积 `≥ 10 KB`（确保正常绘制而非空白） |

### 三条硬契约

| 判据 | 断言 |
|---|---|
| 同一时间栅格 | `raw.size == clip_track.n_frames`，每种模式都成立 |
| 映射输出归一化 | `raw ∈ [-1, 1]` |
| 成形输出归一化 | `shaped ∈ [-1, 1]` 且非空 |

### 成形层物理约束

| 判据 | 断言 |
|---|---|
| 起点回中 | `|shaped[0]| ≤ 1e-9` |
| 终点回中 | `|shaped[-1]| ≤ step_limit` |
| 限速 | `max|diff(shaped)| ≤ step_limit`，其中 `step_limit = max_rate_per_s / control_hz` |

### PWM 层

| 判据 | 断言 |
|---|---|
| 脉宽钳制 | `pulse ∈ [pulse_min_us, pulse_max_us]` |
| 帧数 | `pwm.n_frames == frame_count(shaped.duration_s, pwm_hz)` |

### 模式隔离

| 判据 | 断言 |
|---|---|
| 模式生效 | 各模式的 `raw` 不全相等（否则 `--mode` 未生效） |

> 帧数判据必须调用 `pwm.frame_count()`，不要在测试里自行写 `duration/hz` 或 `duration*hz`。
> 同一个时长用除法与乘法会因浮点误差差出 1 帧（`19.88/0.02` 与 `19.88×50`），实现与测试就会对不上。

### 节拍摆 beat

`beat` 的正确性不是「跟着特征走」，而是「极值有没有踩在拍上」，所以单独用
`tools/verify_beat.py` 验证（合成 100 / 120 / 140 BPM 鼓点，起拍故意偏移到 0.37s）：

```bash
.venv/bin/python tools/verify_beat.py
```

| 判据 | 断言 |
|---|---|
| 摆动周期 | 检出的摆动周期 = 一拍，容差 1% |
| 极值落点 | 成形后极值到拍点的偏差 ≤ **0.25 拍**（容差留给 4Hz 圆角与回中，实测仅 ≈10ms） |
| 左右对称 | 左右两侧行程之差 ≤ 0.05 |
| 摆幅利用率 | ≥ `min(1, 摆动周期 × max_rate_per_s / 2) - 0.12`（低通与死区会再削掉一点） |
| 无节拍安全退化 | 持续音不检出网格，最大摆幅 0.0000 |

### 调参发现

**1. 限速单步上限是「每帧」的概念，不要跨帧心算。**
默认 `max_rate_per_s=2.0`、`control_hz=25` → 单步上限 0.08，即 0.5s 走完归一化全程 ±1。
`control_hz` 与 `max_rate_per_s` 是两个方向：前者决定多密，后者决定多快，不要混用直觉。

**2. 采样率与低通、降采样的顺序不可交换。**
先降采样再低通会混叠出假摆动，且**再怎么限速也去不掉**（见 [architecture.md](architecture.md#1-降采样必须排在低通之后)）。
调 `control_hz` 时先确认它仍低于 `lpf_hz` 的奈奎斯特，否则低通失效。

**3. 「分位归一化」在两处，含义不同，别互相替代。**
- 映射层：决定「特征 → 行程」的形状，分位只定两侧展开范围，**0 点固定取中位数**
  （`norm_low_pct=2 / norm_high_pct=98`）。
- 成形层：只是把映射后已归一的信号按分位**再拉满**，为限速做准备，`low_pct=2 / high_pct=98`。
  `beat` 模式会跳过它（摆幅是按限速刻意算小的，拉满会让极值漂离拍点）。

实测里 pitch 模式最能说明问题：`raw` 只用了约 1/4 行程（`[-0.675, -0.197]`），
但成形后是满幅 `[0, 1]`。也就是说**成形层的归一化会掩盖映射层「没铺开」的问题**——
看报告时要把两行分开读，不能只看最终脉宽曲线。
另外 pitch 的 `raw` 整体在负侧，是因为该合成素材的基频集中在 80~1000Hz 对数中点
（≈283Hz）**以下**，中位数居中后自然偏负；换成正常歌曲两侧都会用到，不是映射缺陷。

**4. 映射层的尖峰会被低通削掉，靠加大 `gain` 补不回来。**
envelope 的 `raw` 是满幅 `[-1.000, +0.992]`，成形后只剩 `[-0.427, +0.329]`，行程被压到约一半。
原因：该模式下正侧极值来自 0.5s 强拍的**衰减脉冲**（测试音频里衰减时间常数仅 50ms），
窄脉冲被 4Hz 低通大幅衰减，而负侧是持续的低能量铺底、几乎不受影响。
不过「中位数居中」已经把它从旧的 `[-0.430, +0.099]`（几乎整段压在负侧）拉回到两侧大致对称。

要扩大成形后的实际行程，优先调整的方向是：

- 提高 `lpf_hz`（保留更多峰值，代价是高频抖动增加）；
- 缩短 `center_ms`、减小 `deadzone`（这两项会再削一点幅度）；
- `gain` 不是首选——它先把信号裁到 ±1，峰值被裁平后低通同样会削，收益有限。

**5. 各模式的差异 100% 来自映射策略。**
`shaping` / `servo` 配置各模式完全共享（见 [architecture.md](architecture.md#7-多模式共用同一套下游配置)），
所以三条曲线对不上时，问题一定在映射层，不必去翻下游参数。展示顺序由 `mappers.ORDER` 固定，便于跨次对照。

**6. 脉宽的两端余量是安全余量，不要为了多几度而放宽。**
600~2400µs 相比标称的 500~2500µs 各留了约 100µs。机械限位处长时间顶死会导致堵转、电流飙升与舵机烧毁，
宁可牺牲一点角度范围。

**7. `beat` 的摆幅是限速的产物，不是算法的近似；想要更大就动限速或摆动周期。**
自动检测取一拍、每拍一个极值（左右交替），摆幅按可达上限反推为 `min(1, max_rate_per_s × 一拍 / 2)`：
120BPM 一拍 0.5s → 摆幅 0.50，此时实测利用率 83.9%；100BPM → 0.60（86.6%）、140BPM → 0.43（81.5%）。
**摆幅小不是缺陷而是物理限制**：舵机在一拍内走不完 2.0 的往返，硬撑满量程只会被限速削波、
极值漂到拍间（听感「慢半拍」）。要更大摆幅，两条路：
调高 `max_rate_per_s`（前提是机械与电源扛得住），或把 `beat_swing_s` 手动填成两拍来放慢节奏（摆幅可翻倍）。

另外两点与「踩点」直接相关：

- 相位不必人工对齐。检测用**圆周均值**求网格相位，结果与「第几拍」无关，
  所以片段起点落在拍间还是拍上都能还原出正确网格；起拍偏到 0.37s 的合成鼓点也能对上。
- **onset 时刻要按窗中心还原**。stft 不做补零居中，第 i 帧覆盖 `[i*hop, i*hop+n_fft)`，
  直接把帧号当事件时刻用会系统性早半个窗（≈46ms）。取窗中心后残差从 57ms 降到 11ms。
  改 `n_fft` 或 `hop_length` 会直接改变这个偏置，所以 `FeatureTrack` 里存了 `n_fft`。

### 推荐调参顺序

1. `--max-seconds 10` 缩短输入，先把截取跑对（必要时 `--start/--end` 手动指定）。
2. 定 `--mode`，先用默认下游参数看 `raw` 与 `shaped` 的差距（报告的上面两行）。
3. `raw` 没铺开 → 调映射层（`--pitch-floor/--pitch-ceil`、`--norm-low/--norm-high`）。
4. `shaped` 太抖 → 降 `--lpf`；跟不上/太慢 → 调 `--max-rate`；零位附近抖 → 调 `--deadzone`。
5. 最后按实机改 `--pulse-min/--pulse-max/--pulse-center`。
6. 每次改动后重跑 `tools/verify_segment.py`，再用 `--mode all` 叠加对比。
