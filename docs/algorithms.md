# 算法与实现细节

## source —— 输入与解码

1. 判断是 URL 还是本地路径，URL 下载到内存（默认超时 30s）。
2. 解码：多声道取均值混为单声道。
3. 重采样到 `SourceConfig.sr`（默认 22050Hz）。
4. `max_duration_s` 非空时只保留前 N 秒，用于快速调试。

重采样目标 22050Hz 的理由：舵机只能响应 3~5Hz 的运动，音频高频信息对最终结果毫无贡献，
22.05kHz 的奈奎斯特频率 11kHz 已经远超谱质心、频段比、f0 所需的频段上限。

## features —— 帧级特征

五项特征，同一栅格。设 `sr`、`n_fft`、`hop`，第 i 帧时间 `i·hop/sr`。

### 帧化

`scipy.signal.stft(pcm, fs=sr, nperseg=n_fft, noverlap=n_fft-hop, boundary=None, padded=False)`

`boundary=None` 关键：**不补零居中**，第 i 帧精确覆盖 `[i·hop, i·hop+n_fft)`。
若用默认的补零居中，帧时间会偏移半个窗，后面做 onset 吸附和片段对齐时会整体错位。

### rms_db —— 能量包络

用累积和法独立计算，O(n) 且与 STFT 帧切分严格一致：

```
squared = cumsum(x²)，前补 0
energy[i] = squared[(i+1)·hop + n_fft] - squared[i·hop]
rms[i]    = sqrt(max(energy[i], 0) / n_fft)
rms_db[i] = 20·log10(max(rms[i], 1e-10))
```

比逐帧循环快一到两个量级，长音频上差别明显。

### spectral_flux —— 谱通量（新颖度）

```
flux[i] = Σ_f max( log1p(|S[f,i]|) - log1p(|S[f,i-1]|), 0 )
```

只累加**正向**变化，所以它衡量的是「新声音出现」的强度，而不是响度。
`log1p` 压缩用来防止单帧爆音主导整条曲线。首帧没有前一帧可比，补 0 保持等长。

### spectral_centroid —— 谱质心（音色明暗）

```
centroid[i] = Σ_f f·|S[f,i]| / Σ_f |S[f,i]|
```

幅度加权的频率平均。越高越「亮」。分母为 0（静音帧）时取 0。

### band_ratio —— 频段能量比

```
ratio[i] = E_high[i] / (E_low[i] + E_high[i])     ∈ [0,1]
```

默认低频段 `[30, 250)Hz`、高频段 `[2000, 8000)Hz`（左闭右开）。
0 = 能量全在低频（鼓、贝斯），1 = 全在高频（镲、气声）。

之所以用「能量比」而不是分别输出两个能量值：比值天然落在 [0,1]，
对整体音量不敏感，映射层不必再做一次归一化就能用。

### f0 —— 基频（YIN）

自实现 YIN，不依赖 librosa。逐帧处理，`τ` 搜索范围由 `f0_min_hz/f0_max_hz` 决定
（默认 80~1000Hz → `τ ∈ [22, 275]`）。

**第一步：差分函数**

```
d(τ) = Σ_j (x[j] - x[j+τ])²
     = Σ_j x[j]²  +  Σ_j x[j+τ]²  -  2·Σ_j x[j]·x[j+τ]
```

前两项用平方累积和算出，交叉项用**一次 FFT 自相关**得到（`irfft(|rfft(x)|²)`），
把每帧复杂度从 O(τ_max·n) 降到 O(n log n)。

**第二步：CMND（累积均值归一化差分）**

```
d'(τ) = d(τ)·τ / Σ_{j=1}^{τ} d(j)，    d'(0) = 1
```

不做这一步，`d(τ)` 在高 τ 处天然偏小，会系统性地把结果拉向低频。

**第三步：取谷**

在搜索范围内取第一个 `d'(τ) < 0.15` 的位置，然后继续下滑到局部极小；
若整段都不低于阈值，退化为取全局最小。

**第四步：抛物线插值**

用谷底邻近三点拟合抛物线，把 τ 细化到亚采样精度，
否则 f0 分辨率被量化到 `sr/τ²`，高音区误差会很明显。

**第五步：浊音判决（关键）**

```
若 d'(τ*) > f0_voiced_ceiling  →  f0 = 0（无基频）
```

少了这道闸，YIN 会给白噪声也硬塞一个「最小差分」对应的假基频，
下游 pitch 映射就会输出一段完全随机的摆动。

实测区分度非常大，所以阈值取 0.35 很宽松：

| 信号 | min-CMND 中位 |
|---|---|
| 纯音 220 / 660 Hz | 0.000 |
| 三和音 440+660+880 | 0.001 |
| 白噪声 | 0.88 |
| 粉噪（累积噪声） | 1.62 |

**实测精度**（1s 正弦，22050Hz）：

| 输入 | f0 中位 | 误差 |
|---|---|---|
| 110 Hz | 110.00 Hz | 0.000 Hz |
| 220 Hz | 220.01 Hz | 0.009 Hz |
| 440 Hz | 440.08 Hz | 0.084 Hz |
| 660 Hz | 660.16 Hz | 0.158 Hz |

浊音判决实测：纯音 / 和音 有效帧 100%，白噪声有效帧 0%。

## segment —— 高潮段截取

### 打分曲线

```
energy  = percentile_norm(rms_db,          P5,  P95)
novelty = percentile_norm(spectral_flux,   P5,  P95)
raw     = 0.7·energy + 0.3·novelty
score   = uniform_filter1d(raw, smooth_s / hop_s, mode="nearest")
```

**平滑这一步不能省**。不平滑时窗口会吸附到单个鼓点上；平滑窗口默认 1.5s，
既能跨过单拍，又不会糊掉段落边界。

### 滑窗选段

对 `score` 做长度为 `window_s` 的滑动求和（累积和实现，O(n)），取积分最大的窗口。
窗口末端不能越界，否则实际切出的片段会短于 `window_s`。

### onset 吸附

选中的起点在 ±`onset_align_s`（默认 0.6s）范围内向前吸附到 `spectral_flux` 的最大值处，
避免从乐句中间切入。吸附后同样做越界钳制。

### 淡入淡出

片段首尾各做 `fade_s`（默认 0.3s）线性淡入淡出，防止第一帧角度跳变。
片段太短（< 2×淡入长度）时跳过，避免整段被压没。

### 手动覆盖

`manual_start_s` / `manual_end_s` 任一非空即跳过自动检测，只做钳制与淡入淡出。
用于「自动切得不对，人工指定区间后再调映射参数」。

## mappers —— 四种映射策略

策略函数直接输出形状 `(n,)`、严格落在 [-1,1] 的行程信号：-1 / +1 为左右极限，0 为中位。
归一化在映射层内部完成，所以下游 shaping / pwm 完全不用改，四种模式才能叠加对比。

前三种是「跟着某个特征走」的连续映射，摆动时机由音乐内容决定；`beat` 反过来
由节拍网格生成信号，是唯一以「踩点」为目标的策略。

### 连续三模式：以中位数为 0 点的双侧归一

envelope / brightness / pitch 都走 `_centered_bipolar`：P(low) → -1、**中位数 → 0**、
P(high) → +1，两侧各自线性铺开（仍用分位而非 min/max，单个爆音不会压扁整条曲线）。

0 点必须落在中位数。若像以前那样把 P2~P98 线性拉到 ±1，中位数落点完全由特征偏态
决定 —— 实测 pitch 的成形输出曾是 `[+0.00, +1.00]`，尾巴整段停在最右边只剩轻微抖动，
这就是「摆动全集中在一侧」。居中后静止位回到中间，两侧行程才是对称的。

### envelope —— 能量包络

`_centered_bipolar(rms_db)`：响处偏向 +1，安静处回落，中位附近居中。
最直观、最容易预期的一种。

### brightness —— 音色明暗

`0.5·(_centered_bipolar(spectral_centroid) + _centered_bipolar(band_ratio))`

取谱质心与高频占比的平均，抵消单一指标的偏科：
谱质心对宽频噪声敏感，高频占比对低频鼓点敏感，两者平均后更接近「主观明亮度」判断。

### pitch —— 基频高低

```
无基频帧 → 用相邻有效帧线性插值补齐（首尾常数外推）
middle = ½·(log2(floor) + log2(ceil))
value  = (log2(clip(f0, floor, ceil)) - middle) / (½·(log2(ceil) - log2(floor)))
```

以 floor / ceil 的**对数中点**为 0：floor → -1、ceil → +1，中位音高就落在中位。

**对数刻度**是必须的：人耳对音高的感知本身就是对数关系，
线性刻度会让低音区挤在一起、高音区铺满整个行程。

### beat —— 节拍摆

与前三种相反：它不跟任何特征走，而是先把节拍网格定出来，再生成一条
「极值刚好落在拍点上」的对称三角波。链路是
`谱通量 → onset → 周期扫描 → 网格拟合 → 三角波`：

1. **守卫**：`rms_db` 的 95 与 5 分位之差 < `beat_min_dynamics_db` 就直接返回静止居中。
   持续音/长音垫/白噪的谱通量只是浮点噪声，却在帧栅格下表现为准周期，
   逐帧判据全都拦不住；响度动态范围是唯一分得开的量（真实歌曲 ≥6.6dB，非节拍素材 ≤0.68dB）。
2. **onset**：自适应阈值（局部中位数 × `beat_threshold`）+ 局部极大 + 最短间隔贪心去重。
3. **周期**：在 `beat_bpm_range` 内按 1ms 步长扫候选周期，相位用**圆周均值**求，
   残差取各 onset 到最近网格点的 RMS 距离；合格者里取**周期最大**的 ——
   真节拍的整数分之一也能量踩中所有 onset，取小会系统性翻倍。
4. **精修**：对 (拍号, 时刻) 做最小二乘线性回归得到小数周期，收掉累积漂移。
5. **成形**：`envelope` 等模式是「特征驱动」，`beat` 是「网格驱动」，
   所以它的取样点必须用**窗中心** `frame*hop_s + n_fft/(2*sr)` 还原，
   否则会系统性早半个窗（≈46ms）。
6. **波形**：三角波而非半余弦。三角波斜率恒为 `2·摆幅/摆动周期`，摆幅按限速反推成
   `min(1, max_rate_per_s × 摆动周期 / 2)` 后斜率正好等于限速上限，是限速下唯一
   能按时到点的形状；半余弦在极值处斜率为 0、起步太慢，实测 120BPM 极值晚 80ms，
   三角波 0ms。拐角会被成形层 4Hz 低通磨圆，观感不生硬。

自动检测取**一拍**：相邻极值隔一拍、左右交替，所以每个节拍都到一次边
（7 个音的乐句 → 左右左右左右左，奇数拍让下一句自然从另一侧起）。
摆幅不是满量程而是按限速反推的可达值，因此极值**始终落在拍点上** ——
120BPM（一拍 0.5s、限速 2.0/s）摆幅约 0.50，100BPM 约 0.60，140BPM 约 0.43。
以前取两拍是为了绕开限速、保住满行程，代价是每隔一拍才到一次边，听感就是「卡不准」。

想让摆幅更大，把 `beat_swing_s` 手动填成两拍（半速摆动，摆幅可翻倍），
或调高 `max_rate_per_s`（前提是机械与电源扛得住）。

### 统一收尾（`map_track`）

```
NaN/inf 清理 → 去毛刺平滑（50ms）→ 方向翻转（invert）→ 增益（gain）→ 裁剪到 [-1,1]
```

平滑用 `uniform_filter1d(mode="nearest")`。
这里只去逐帧尖峰，**不做带宽约束**——那是成形层的职责，两处都做会互相掩盖问题。

## shaping —— 物理约束

输入：片段帧栅格的 [-1,1] 信号 + `hop_s`。输出：控制帧率（默认 25Hz）的 `ShapedTrack`。

### 1. 分位数归一化

`x → clip((x - P2)/(P98 - P2) · 2 - 1, -1, 1)`。把实际用到的行程拉满，
否则可能只用到中间很小一段角度，「舵机几乎不动」。区间退化（P98 ≈ P2）时输出全 0。

`shape(..., rescale=False)` 可跳过这一步，**只给 beat 用**：beat 的摆幅是按限速
刻意算小的，再拉满会让斜率超过限速、被限速器削成更小且极值漂到拍间的三角波。

### 2. NaN 填充

`np.interp` 在有限值索引上插值，两端常数外推。映射层正常不会输出 NaN，
这一步是防御性的，但必须排在低通**之前**——滤波器遇到 NaN 会污染整段输出。

### 3. 低通

```
butter(order=2, cutoff=lpf_hz / (0.5·fs))  +  filtfilt   # 零相位
```

用 `filtfilt` 而非 `lfilter`：**零相位**意味着没有群延迟，
不需要在下游补偿相位，限速和回中的时序判断才准。

跳过条件：`lpf_hz >= 0.45·fs`（截止频率接近奈奎斯特，滤波无意义），
或信号长度 `<= 3·max(len(a), len(b))`（`filtfilt` 会因 padding 失败）。

### 4. 降采样

```
dt = 1/control_hz
control_times = arange(count)·dt，  count = round(duration/dt) + 1
values = interp(control_times, frame_times, values)
```

必须排在低通之后（见 [architecture.md](architecture.md#1-降采样必须排在低通之后)）。

### 5. 限速

```
step = max_rate_per_s / control_hz
g[0] = x[0]
g[i] = g[i-1] + clip(x[i] - g[i-1], -step, +step)
```

纯前向累积，不回头修正，所以结果是**因果**的——和真实舵机的行为一致：
舵机也只能根据当前位置往目标靠。

### 6. 死区（软）

```
x → sign(x) · max(|x| - deadzone, 0)
```

用「减去宽度」而不是「小于阈值直接归零」，保证在阈值处**连续**。
硬死区会在 `|x| = deadzone` 处产生跳变，限速若在之前生效，跳变就会被漏掉。

### 7. 首尾回中

斜坡长度 `max(center_ms·control_hz/1000, ceil(|anchor| / max_rate_per_s · control_hz))`——
下限保证基本的过渡时长，第二项按限速反推最短可行时间。
首尾各乘一次斜坡，起点严格为 0，终点回到中位。

### 8. 限速（最终钳位）

回中之后再过一次限速，保证全程单步位移可证明不超过上限。
理由见 [architecture.md](architecture.md#4-回中之后追加一次限速--对原定顺序的一处偏离)。

## pwm —— PWM 帧生成

### 帧数

```
frame_count(duration_s, pwm_hz) = floor(duration_s · pwm_hz + 1e-6) + 1
```

**必须集中在这个函数里算**。同一个时长，调用方写 `duration/period` 与 `duration·hz`
会因浮点误差得到相差 1 的结果（例如 `19.88/0.02 = 993.9999…` 而 `19.88×50 = 994.0000…`），
验证脚本和实现就会对不上。

### 插值上采样

控制帧 25Hz → PWM 帧 50Hz，用 `np.interp` 线性过渡。

舵机每 20ms 需要一个明确的目标脉宽。如果不插值而直接保持上一帧，
舵机就会「停 40ms → 突跳」，等效于给系统加了一串阶跃激励。
线性插值把台阶变成斜坡，配合前面的 4Hz 低通，整体运动是连续的。

### 标定（分段线性）

```
angle_deg = value · angle_max_deg
pulse_us  = center + value·(max - center)     value ≥ 0
          = center + value·(center - min)     value < 0
```

分段而非单段斜率的理由：真实舵机的中位往往不在 500~2500µs 的正中，
用两段斜率可以独立校准两侧行程，保证 `value = 0` 严格对应 `pulse_center_us`。

### 钳制

最后再 `clip(pulse_us, pulse_min_us, pulse_max_us)` 一次。
即使上游给到 ±1 之外，也不会把舵机顶到机械限位上堵转。

### CSV 输出

```
mode,frame,time_s,pulse_us,angle_deg,value
envelope,0,0.0000,1500.0,-0.00,-0.0000
...
```

`mode` 列让多模式的帧序列共存于一个文件，便于并排对比。
`value` 列是插值后的归一化行程，用来核对「上游信号 → 脉宽」的映射是否如预期。
